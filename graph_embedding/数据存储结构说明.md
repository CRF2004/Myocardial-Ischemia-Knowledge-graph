# 图谱嵌入数据存储结构说明

## 概述

本文件夹包含两个核心文件，用于存储图谱节点的向量嵌入及其元数据：
- `/mnt/chengrongfeng_private/SRP心肌缺血知识图谱/graph_embedding/knowledge_embeddings.faiss` - FAISS 向量索引文件
- `/mnt/chengrongfeng_private/SRP心肌缺血知识图谱/graph_embedding/knowledge_embeddings_metadata.pkl` - 元数据文件

### 核心特性
- **增量更新**: 支持自动检测并只处理新节点，避免重复计算
- **向量归一化**: 所有向量经过L2归一化，使用内积距离进行相似度计算
- **高效检索**: 基于FAISS的IndexFlatIP索引，支持快速语义相似度搜索

## FAISS 文件结构 (`knowledge_embeddings.faiss`)

### 存储内容
FAISS 文件存储所有图谱节点的向量嵌入，使用 FAISS 的 `IndexFlatIP` 索引类型。

### 索引特性
- **索引类型**: `IndexFlatIP` (基于内积的精确搜索)
- **向量维度**: 1536 (使用 OpenAI `text-embedding-3-small` 模型)
- **数据类型**: `float32`
- **向量数量**: 动态增长，支持增量更新
- **向量归一化**: 所有向量经过 L2 归一化处理（`faiss.normalize_L2`）

### 内积距离 vs 欧几里得距离
- 使用 `IndexFlatIP` 配合 L2 归一化，内积距离等价于余弦相似度
- 余弦相似度更适合文本语义相似度计算，不受向量长度影响
- 相比欧几里得距离，更能准确反映语义相似程度

### 向量生成逻辑
每个节点的向量基于以下文本内容生成：
1. **Knowledge 节点**: 优先使用 `normalized_name` 属性
2. **ECGFinding 节点**: 使用 `name` 属性
3. **DiscoveryKnowledge 节点**: 使用 `name` 属性
4. **Ontology 节点**: 使用`name_en` 属性 
5. **其他节点**: 组合可用的名称和定义信息

### 增量更新机制
系统支持增量更新，避免重复生成已有节点的embedding：

1. **检测已有数据**
   - 检查 `knowledge_embeddings_metadata.pkl` 是否存在
   - 加载已有节点的 `node_ids` 列表和 `texts` 列表
   - 构建 `existing_node_ids_set` 用于快速查找

2. **识别新节点**
   - 从 Neo4j 获取所有节点
   - 对比节点ID，筛选出不在 `existing_node_ids_set` 中的节点
   - 只为新节点生成embedding

3. **验证维度一致性**
   - 加载已有FAISS索引时验证维度
   - 确保新向量维度与索引维度一致
   - 如果维度不匹配则报错退出

4. **追加更新**
   - 对新向量进行L2归一化
   - 使用 `index.add()` 追加到已有索引
   - 合并 `node_ids` 和 `texts` 列表

5. **统计信息**
   - 输出原有节点数、新节点数、总节点数
   - 验证 `index.ntotal` 与总节点数一致

## 元数据文件结构 (`knowledge_embeddings_metadata.pkl`)

### 数据格式
使用 Python `pickle` 序列化，存储为字典结构：

```python
{
    "node_ids": List[int],      # 节点ID列表
    "texts": List[str],         # 对应的文本内容列表
    "dimension": int            # 向量维度
}
```

### 字段说明

#### `node_ids` (List[int])
- **类型**: 整数列表
- **说明**: Neo4j 图谱中节点的唯一标识符
- **来源**: `node.identity` (py2neo 节点对象的 ID)
- **索引关系**: `node_ids[i]` 对应 FAISS 索引中的第 i 个向量

#### `texts` (List[str])
- **类型**: 字符串列表
- **说明**: 用于生成向量的原始文本内容
- **用途**: 用于向量搜索时的结果展示和上下文理解
- **索引关系**: `texts[i]` 对应 `node_ids[i]` 的文本内容

#### `dimension` (int)
- **类型**: 整数
- **说明**: 向量的维度大小
- **当前值**: 1536
- **用途**: 验证向量维度一致性，确保索引兼容性

## 数据一致性保证

### 索引映射关系
```
FAISS 索引位置 i  <--->  node_ids[i]  <--->  texts[i]
```

三个数组的索引严格对应，确保：
- FAISS 索引中的第 i 个向量属于 `node_ids[i]` 节点
- 该向量基于 `texts[i]` 文本生成

### 增量更新流程
1. **加载现有元数据**
   - 检查 `knowledge_embeddings_metadata.pkl` 是否存在
   - 如果存在，加载 `node_ids`、`texts`、`dimension`
   - 构建 `existing_node_ids_set` 用于快速查找

2. **获取所有节点**
   - 从 Neo4j 查询所有节点：`MATCH (n) RETURN n`
   - 提取节点ID、标签、属性

3. **识别新节点**
   - 遍历所有节点，提取用于embedding的文本
   - 过滤条件：文本非空 且 节点ID不在已有集合中
   - 收集 `new_texts` 和 `new_node_ids`

4. **生成新向量**
   - 调用 `get_embedding("text-embedding-3-small", new_texts)`
   - 转换为 numpy 数组，数据类型为 `float32`

5. **加载或创建FAISS索引**
   - 如果索引文件存在，使用 `faiss.read_index()` 加载
   - 如果不存在，创建新的 `IndexFlatIP(dimension)`
   - 验证新向量维度与索引维度一致

6. **归一化并添加向量**
   - 执行 `faiss.normalize_L2(new_embedding_array)`
   - 使用 `index.add(new_embedding_array)` 追加向量

7. **更新元数据文件**
   - 合并：`all_node_ids = existing_node_ids_list + new_node_ids`
   - 合并：`all_texts = existing_texts_list + new_texts`
   - 保存更新后的元数据到 `knowledge_embeddings_metadata.pkl`
   - 保存FAISS索引到 `knowledge_embeddings.faiss`

## 使用场景

### 向量搜索
1. 对查询文本生成向量嵌入
2. 使用 FAISS 索引进行最近邻搜索
3. 通过返回的索引位置，从元数据中获取对应的节点 ID 和文本

### 数据验证
- 检查 `index.ntotal` 是否等于 `len(node_ids)`
- 验证 `dimension` 是否与向量维度一致

## 示例代码

```python
import faiss
import pickle
import numpy as np

# 加载 FAISS 索引
index = faiss.read_index("knowledge_embeddings.faiss")

# 加载元数据
with open("knowledge_embeddings_metadata.pkl", "rb") as f:
    metadata = pickle.load(f)

# 查询示例
query_text = "心肌缺血的诊断方法"
query_vector = get_embedding("text-embedding-3-small", [query_text])
query_vector = np.array(query_vector, dtype='float32')

# 重要：查询向量也需要L2归一化，与索引向量保持一致
faiss.normalize_L2(query_vector)

k = 5  # 返回最相似的 5 个结果
distances, indices = index.search(query_vector, k)

# 获取结果（内积距离，范围在-1到1之间，越接近1表示越相似）
for i, idx in enumerate(indices[0]):
    node_id = metadata["node_ids"][idx]
    text = metadata["texts"][idx]
    similarity = distances[0][i]  # 内积距离，等价于余弦相似度
    print(f"节点ID: {node_id}, 文本: {text}, 相似度: {similarity:.4f}")
```

### 查询向量处理注意事项
- 查询向量必须经过 **L2 归一化** 才能获得正确的内积距离
- 由于索引向量已归一化，内积距离等价于余弦相似度
- 相似度范围：[-1, 1]，值越接近1表示越相似

## 注意事项

1. **文件同步**: FAISS 文件和元数据文件必须保持同步更新
2. **维度一致性**: 任何更新都必须确保向量维度相同
3. **索引顺序**: 不要手动修改元数据文件的顺序，会破坏映射关系
4. **备份建议**: 在大规模更新前建议备份现有文件
5. **向量归一化**: 所有向量（包括索引向量和查询向量）必须经过L2归一化
6. **增量更新**: 系统会自动检测新节点，无需手动清空重建
7. **距离解释**: 使用内积距离（IndexFlatIP），等价于余弦相似度，范围[-1, 1]
